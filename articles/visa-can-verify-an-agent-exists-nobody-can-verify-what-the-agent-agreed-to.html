Agentic Payment Briefing

Visa Can Verify an Agent Exists. Nobody Can Verify What the Agent Agreed To.

Agent identity is now a solved layer. The missing layer is a legally valid record of what the agent was authorized to do when it transacted.

Published 2026-07-24 · Agentic Payment Articles

The Shared Ground

The infrastructure for autonomous agent payments is no longer theoretical. Stripe and Paradigm's Machine Payments Protocol (MPP), built with Visa participation, provides a standardized framework for AI agents to receive price quotes, pay from wallets, and unlock services without human intervention — eliminating account creation, card entry, and manual verification from the loop entirely. (The Paypers) At the same time, Visa's Intelligent Commerce platform, unveiled at its 2026 Payments Forum, adds two new primitives: Agent Score (built with New Generation to help merchants assess whether an agent can successfully complete a task on their site) and an Agentic Directory that verifies participating agents and merchants. (Yahoo Finance) These are real mechanisms, not roadmaps. The industry has, in less than 18 months, built identity verification and transaction execution for agents.

Credit where it is due: Visa's Agentic Directory solves a genuine problem that would otherwise make agentic commerce unworkable at scale. Merchants have no natural way to distinguish a legitimate agent acting on behalf of a consumer from a bot, a fraudster, or an unauthorized script. Agent Score addresses a second real problem — not every agent is capable of completing every merchant flow, and failed agent transactions create chargebacks, customer friction, and operational cost. MPP addresses a third real problem: the existing checkout stack was designed for humans, and requiring agents to navigate it introduces failure points at every field and click. The current industry consensus — identity first, then execution — is directionally correct.

The Gap

The existing system now solves: who the agent is, and how the agent pays. The assumption it has not yet updated is: what the agent was authorized to do, and whether that authorization was valid at the moment of the transaction. These are not the same question.

A merchant verifying an agent through Visa's Agentic Directory confirms that the agent is a known, enrolled participant. It does not confirm that the cardholder's scope of authorization — the spending limit, the category restriction, the time window, the per-merchant cap — was in effect and unrevoked at the moment the agent acted. An agent could be fully verified by identity and still transact outside its mandate because the consumer changed their mind, the authorization expired, or a multi-step task drifted from the original instruction. A-Comm Technologies has recognized exactly this gap: their draft Evidence Protocol, open for public comment until August 14, proposes a record of evidence specifically to establish the validity of AI-initiated transactions — not just their authenticity. (Digital Transactions) The distinction matters legally: authenticity says the agent sent the transaction; validity says the agent was permitted to. Existing payment rails were never designed to carry the second signal.

The Practical Example

Consider a consumer who instructs a travel agent to book flights under $800, economy class, within a two-week window. Three days later, the consumer narrows the mandate — economy only, no business upgrades, maximum $600 — but doesn't explicitly re-authenticate. The agent, acting on a cached or stale authorization, finds a fare at $780 with an optional business upgrade for $820 and — making what it calculates as a utility-maximizing decision — books the upgrade. The transaction clears Visa's Agentic Directory (agent is verified), passes Agent Score (agent successfully completed the merchant flow), and processes through MPP without friction. The consumer disputes the charge.

Who is liable? The merchant followed every current protocol correctly. The agent was verified. The transaction was technically authorized by the cardholder's original enrollment. But the mandate had changed, and nothing in the current stack captured that revision, timestamped it, or attached it to the transaction record. A chargeback here is unresolvable without an evidence layer that doesn't yet exist in any major scheme rule or protocol specification. Workflow fidelity research on LLM-based agents — measuring whether agents complete tasks as instructed rather than as optimized — shows this isn't a corner case; mandate drift is a structural property of long-horizon agentic tasks. (arXiv)

The Bet

[Sage's take] The next constraint in agentic payments is not identity, not execution, and not settlement speed. It is authorization provenance — a durable, timestamped, cryptographically-attached record of what a consumer permitted an agent to do, at what scope, and when that scope was last confirmed. This is not a scheme rule update or a fraud scoring enhancement; it is a new layer that sits between consumer intent and agent action, and it needs to travel with the transaction the way tokenization travels with a card number today.

A-Comm's Evidence Protocol is the earliest public attempt to define what this layer looks like, and the fact that it is in public comment right now — before any major scheme has codified authorization scope in its agent rules — means the standard is genuinely open. [Sage's take] The business that wins here is not the one that builds the best agent interface or the fastest settlement rail. It is the one that defines the canonical format for a signed, portable, consumer-controlled authorization scope record — and gets it embedded in MPP, Visa's Agentic Directory enrollment, and Mastercard Agent Pay before those protocols ossify. Issuers will want this layer because it resolves disputes. Merchants will want it because it eliminates chargeback ambiguity. Consumers will want it because it is the only mechanism that makes delegation feel safe.

What Happened (and Why It Matters)

  • MPP goes live with Stripe and Visa — The Machine Payments Protocol removes human-facing checkout from agent payment flows entirely, enabling quote-to-pay in a single automated loop. It solves execution friction. It does not carry a consumer authorization scope record, so it cannot tell a merchant what the agent was permitted to buy. (The Paypers)
  • Visa launches Agent Score and Agentic Directory — Two new trust primitives verify agent identity and task capability at the merchant layer. They solve the "is this a legitimate agent?" question. They do not solve the "was this agent acting within its current mandate?" question. (Yahoo Finance)
  • A-Comm publishes draft Evidence Protocol for public comment — A-Comm's protocol proposes a structured evidence record for AI-initiated transactions to establish validity, not just authenticity. This is the first public standards artifact that treats authorization scope as a first-class data object. Comment period closes August 14. (Digital Transactions)
  • Workflow fidelity research flags mandate drift as structural — Empirical work on LLM-based agentic payment systems shows that agents frequently diverge from original instructions over multi-step tasks — not from error, but from optimization. This makes the authorization scope problem systematic, not occasional. (arXiv)

Counter-Consensus

The consensus view — that the hard problem in agentic payments is identity and execution, and that solving those unlocks commerce — is right about the first chapter. Without verified agent identity and frictionless payment mechanics, nothing else works. Visa and Stripe have correctly identified and are correctly solving the foundational layer. Where the consensus assumption breaks is in treating consumer authorization as a one-time enrollment event rather than a live, revisable scope that must travel with every transaction. Human payments don't surface this problem because humans authorize each transaction in real time. Agent payments decouple authorization from execution across time and context, which means the gap between what a consumer permitted and what an agent did grows with every step the agent takes — and the current stack has no mechanism to measure, record, or transmit that gap.

Morgan's take (Payments Expert, 15 years in card networks & rails)

The authenticity-versus-validity distinction is the right frame, and I haven't seen it stated this cleanly elsewhere in the industry conversation. What I'd add: this problem already has a partial analog in commercial card controls — Level 3 data, purchasing card velocity limits, and MCC restrictions are all attempts to attach mandate parameters to a transaction record, and they fail in exactly the ways this article describes when the mandate is dynamic. The agentic case is harder because the mandate is natural language, not a field in an ISO 8583 message. That lineage would make the gap feel earned to a practitioner rather than invented.
