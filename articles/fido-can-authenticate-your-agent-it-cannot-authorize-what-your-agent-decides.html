Agentic Payment Briefing

FIDO Can Authenticate Your Agent. It Cannot Authorize What Your Agent Decides.

Authentication proves an agent is who it claims. The missing layer is authorizing what the agent is allowed to decide—and that gap is where liability lands.

Published 2026-07-19 · Agentic Payment Articles

The Shared Ground

The existing authentication stack is not naive. FIDO2/WebAuthn solved a real problem: phishing-resistant, device-bound credential verification that removes shared secrets from the authentication flow. FIDO Alliance's current mandate to extend these standards to AI agents—defining how agents authenticate, act, and transact on behalf of end users—is a logical continuation of that work. The protocols exist, they scale, and they are trusted by every major browser, device manufacturer, and payments network. Stripe's Agentic Commerce Suite, announced at Sessions 2026, builds on this by letting businesses expose purchase endpoints to agents, with Stripe Link providing tokenized payment references rather than raw card numbers. Visa's completed secure AI transaction pilots establish agent-compatible credential flows at network scale. The stack from credential to token to network rail is, in broad strokes, coherent.

So is the agent market it is being built for. The AI agents market sits at $7.84 billion in 2026 and is projected to reach $52.62 billion by 2030, with autonomous decision-making agents as the fastest-growing segment. The infrastructure investment is rational. The authentication conversation is necessary. The credential and tokenization layers solve real, solvable problems—and the industry is rightly solving them. (Precedence Research) (Nevermined)

The Gap

Authentication answers one question: is this agent who it claims to be? Authorization answers a different question: is this agent permitted to make this specific decision, right now, given what has changed since the user last expressed a preference? The existing system solves the first. It does not solve the second.

FIDO's own framing of the problem is revealing: existing standards were designed for direct human interaction, not delegated agent action. The concern named is trust, liability, and user consent. But the proposed remedy—extending authentication standards to agents—addresses identity continuity, not decision scope. A token proves an agent is authorized to transact. It does not encode what spending logic was approved, under what conditions that approval lapses, or what happens when context shifts between the user's last instruction and the agent's next transaction. The compliance gap is equally stark: European PSPs operating under PSD2 and forthcoming AI Act provisions have no current framework for attributing liability when an authenticated, tokenized agent makes a payment the user would have rejected had they been asked. Authentication is necessary but not sufficient—and the industry is currently treating it as if it were both. (Tech Channels) (Finance X Magazine)

The Practical Example

A user instructs a travel agent to book the cheapest available flight to Berlin for a conference, budget capped at €400. The agent authenticates via FIDO-compliant credential, receives a scoped payment token from Stripe, and begins searching. Three hours later, the cheapest option is a €387 fare with a 48-hour layover. The agent books it—it is within scope, the token is valid, the authentication is unimpeachable. The user misses the conference. The dispute hits the issuer: was this authorized? Under current rules, yes—the credential was valid, the token was used within its parameters, the merchant completed a legitimate transaction. The user's actual intent (arrive in time for the conference) was never encoded anywhere the payment system could read it. The authorization layer stopped at "agent is real and token is valid." No existing protocol captured the conditional logic the user actually meant. The chargeback process was designed for card fraud, not for semantic drift between user intent and agent execution. (Reddit/AI_Agents)

The Bet

[Sage's take] The constraint that changes next is not authentication—that problem is being solved competently. The constraint is delegated authorization scope: a machine-readable, auditable record of what a user actually intended the agent to optimize for, the conditions under which that authorization expires or requires re-confirmation, and which party bears liability when the agent's reasoning drifts from that scope. This is not a credential problem. It is a policy problem that needs to be expressed at the protocol layer.

The businesses positioned to build this are not the card networks or the FIDO Alliance—they are the platforms that sit between user intent and agent execution: the orchestration layers, the agent wallet providers, and the compliance tooling vendors who can encode authorization policies as structured, versioned objects that travel with the payment context. Stripe, notably, is closer than most—its bounded payment reference architecture is a first approximation of scoped authorization. But the assumption that needs updating is this: the industry is treating agent payment safety as an authentication and tokenization problem. It is actually a policy legibility problem. Until user intent can be expressed in a form that issuers, networks, and dispute resolution systems can parse, the liability from every semantically-misaligned agent transaction will land somewhere arbitrary—and that uncertainty will slow adoption faster than any credential gap.

What Happened (and Why It Matters)

  • FIDO Alliance moves to define agent authentication standards — Extends phishing-resistant credential standards to AI agents acting on behalf of users. Solves identity continuity; leaves decision-scope authorization entirely unaddressed. (Tech Channels)
  • Stripe Agentic Commerce Suite launches at Sessions 2026 — Businesses can now sell through AI agents using tokenized payment references, keeping raw card data out of agent context. Solves PCI exposure; does not encode what the agent is permitted to decide within a purchase flow. (Tech Channels)
  • Visa completes secure AI transaction pilots, targets Holiday 2026 mainstream — Agent-compatible credential and acceptance infrastructure validated at network scale. Forecasts millions of autonomous checkouts daily. Creates volume pressure on dispute and liability frameworks that were not designed for this traffic class. (AI CERTs) (Visa Investor Relations)
  • European PSPs face compliance gap with no regulatory framework yet — PSD2 strong authentication requirements apply to the credential, not to the agent's decision logic. AI Act provisions for high-risk automated decisions have not been mapped to payment authorization flows. (Finance X Magazine)
  • IJISAE paper identifies hallucination detection and payment governance as open challenges — Academic synthesis confirms that multi-agent payment systems require cryptographic trust and governance frameworks—authentication alone is insufficient for production safety. (IJISAE)

Counter-Consensus

The consensus is right that authentication is the foundation—you cannot build authorization scope without knowing which agent you are scoping. FIDO's extension work and Stripe's tokenized reference architecture are genuine progress, not theater. The assumption that needs updating is that solving authentication creates a safe agentic payment system. Authentication proves the agent's identity is stable. It says nothing about whether the agent's reasoning stayed within the user's actual intent across a multi-step, time-delayed task. When Visa processes millions of autonomous checkouts daily by late 2026, the disputes that follow will not mostly be about stolen credentials—they will be about agents that were correctly authenticated and incorrectly scoped. The industry needs to build the policy legibility layer before that volume arrives, not after the first wave of chargebacks forces the question.

Morgan's take (Payments Expert, 15 years in card networks & rails)

The dynamic linking requirement under PSD2 RTS Article 5 is the sharpest edge of this problem that nobody in the agentic payments conversation is talking about precisely enough: if an agent re-prices and re-executes a transaction hours after user instruction, the cryptographic binding between authentication and the specific transaction — amount, payee, timestamp — is broken by definition. European issuers cannot treat that as SCA-compliant without a rule change, and right now there is no rule change on the table. That is the regulatory exposure that should anchor the compliance section.
